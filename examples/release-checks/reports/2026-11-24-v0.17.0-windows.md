## Migration d'un projet 0.16.1

Environnement installé en 0.16.1, projet initialisé, deux tâches (`add-greeting` en consultation, `open-draft` en brouillon), puis `pip install --upgrade` de la roue 0.17.0.

| Commande | Résultat |
|---|---|
| `check` avant `sync` | Sortie 0 : « instructions match the project profile » |
| `task list` | Lit les deux tâches et leur statut |
| `integrations --host other` | Le skill 0.17.0 est déjà en place, rien n'est réécrit |
| `sync` | Réécrit `AGENTS.md`, crée `catalog.lock.json`, nomme `add-greeting` comme consultée sous les règles précédentes |
| `profile set host claude-code` | Sortie 1 : l'hôte est déjà `claude-code`. `host apply` écrit ensuite `.claude/settings.json` et `host check` dit « Nothing missing » |
| `update`, `check` | « 0 records changed since the project's lock », `check` sort avec 0 |
| Fichiers des tâches | Inchangés : `add-greeting.json` `ddc2b09b…`, `open-draft.json` `034f731e…` |

La fixture `tests/fixtures/upgrade/v0.16.1.json` (approbation 0.16.1 sans sceau, SHA-256 du fichier `9856893a…`) :

- `check` sort avec 1 et nomme l'approbation sans sceau, avec la commande `task consult request-status --reuse-answers`. `task show` lit la tâche. Le fichier reste identique après `sync`.
- `task consult request-status --reuse-answers` sans réponse, y compris avec l'entrée standard fermée, affiche la question `concerns` puis « EOF when reading a line » (sortie 1). Sur cette installation, `sys.stdin.isatty()` reste vrai quand l'entrée est le périphérique `NUL` : le chemin « sans terminal, consulter en `unsure` » du changelog ne s'enclenche pas. Le chemin documenté avec un fichier fonctionne : `--reuse-answers --answers` et `{"concerns": ["none"]}` consulte à nouveau, l'ancienne approbation ne tient plus, et `check` sort ensuite avec 0.

## Limites

- Le contrôle exécuté est une commande Python du profil de la recette, pas `python -m pytest` de l'exemple `request-status`.
- La migration automatique « sans terminal » échoue sur Windows tant que `NUL` est vu comme un terminal. Le fichier de réponses, lui, passe.
- Linux et macOS de cette release sont couverts par l'exécution GitHub citée plus haut, pas par cette session.
