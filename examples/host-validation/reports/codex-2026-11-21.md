# Codex, 2026-11-21

Host: Codex CLI 0.171 on macOS, run with `codex exec` (one turn per message, `codex exec resume` for the next ones), sandbox `workspace-write`, the user's own configuration ignored. Project: a copy of `project/` with `host` set to `codex` and `boards` limited to `product` and `security` to keep the runs short; research policy `local-only`. OpenGuildKit from `main` on the day of the run, installed with `openguildkit integrations --host codex` and `openguildkit host apply`. The person's part (answers, decision) was played by the maintainer who ran the test, outside the agent.

The project was not marked as trusted, so Codex did not load `.codex/config.toml` or `.codex/rules/`: the two enforced controls were not exercised. What follows is what the skill and `AGENTS.md` alone made the agent do.

## Task 1: export of a customer's own requests

The request was given in plain words, without any command.

| Turn | What the agent did |
|---|---|
| 1 | Read the skill, ran `task new`, read the project, ran `task questions`, proposed the scope and asked three questions. No file changed. |
| 2 | After the answers: `task route`, `task consult`, one `task pass ... --mode subagent` per board, each given to a subagent. Both entries were accepted at the first `task submit`. `task review --summary` recorded `execution: subagents`. `task deliberate` (no objection: both boards answered `proceed`, medium confidence), `task challenge`, `task blockers`. It then gave the person the `task decide` command and said it would not run it. |
| 3 | After the person approved in a terminal: `task handoff`, implementation of `export_requests_csv` with seven new tests, `task verify` (the project check passed), `task result`, `task complete`, `task export`. Final state: `done`. |

Evidence recorded by the boards: the two project files with line ranges, the test command, and the requester's scoping answers. Security's four findings were observed; Product marked one finding as an assumption and one as missing (no baseline to measure the outcome).

## Task 2: a recommendation without market data

One turn. The agent removed the Security board from the consultation with a reason of its own (`task consult --remove security --reason ...`), gave the Product pass to a subagent, and recorded the verdict `insufficient-evidence` with low confidence. It made no web search and changed no file, gave a provisional recommendation and stopped for the decision.

## Task 3: a public share link

One turn. Product and Security both answered `revise`, with two blockers each (owner-authorised creation, expiry, revocation, the fields shown). The agent listed the decisions to take, named who owns each, and stopped. No file changed.

## What these runs showed about OpenGuildKit

- The agent could not find the format of the result file and read OpenGuildKit's source to learn it. `task result ID --template` now prints a file to fill.
- The agent removed a board on its own initiative, and the decision brief did not show it. Since then the brief and the approval prompt list every board added or removed, and the person confirms the removal of a board that the data answer selected (issue 98).
- A scoping answer the agent wrote in its first turn was rejected in the second because it had been given no write access on resume: `codex exec resume` takes its sandbox from `-c sandbox_mode=...`, not from `-s`.
