# Command reference

For: anyone who looks up a command or an option of the CLI, or writes a script around it.

Generated by `python scripts/cli_reference.py` from the parser of the CLI. Do not edit this page by hand: `tests/test_completion_cli.py` fails when it is out of date.

`openguildkit COMMAND --help` prints the same text for one command, and `openguildkit completion bash` or `zsh` prints a script that completes it. These options come before the command, or after it:

- `--version`: show program's version number and exit
- `--project PATH`: Project root (defaults to the closest configured ancestor). It may also follow the command.
- `--policy-repo PATH`: Local Git repository with the central export rule.
- `--policy-commit SHA`: Full Git SHA of the central policy commit.

## catalog

- `--json`: Print the complete catalog as JSON.

## references

- `[QUERY]`: Search reference names and descriptions.
- `--family FAMILY`: Show references from one family ID.
- `--id ID`: Show one reference and its sources.
- `--json`: Print matching references as JSON.

## patterns

List stack patterns and work methods.

- `--role ROLE`: Filter by role ID.
- `--id ID`: Show a pattern, its match and its rule packs.
- `--json`: Print matching patterns as JSON.

## preview

Show the rule packs, their origin and scope before writing them.

- `--answers FILE`: Preview setup answers instead of the saved profile.
- `--json`: Print the plan as JSON.

## detect

Propose components and technologies from the repository's manifests.

- `--json`: Print the components and their evidence as JSON.

## recommend

Preview patterns for a project context.

- `--answers FILE`: Read sector, stack and roles from a JSON file.
- `--json`: Print matches and suggestions as JSON.

## brains

List the specialist review boards.

- `--id ID`: Show a brain's specialist lenses and review criteria.
- `--json`: Print the board definitions as JSON.
- `--check`: Fail when a brain has no method or no reference.
- `--new ID`: Write the skeleton of a project brain in .openguildkit/catalog.

## init

Initialize a project profile and agent instructions.

- `--questions`: Print the setup questionnaire as JSON.
- `--answers FILE`: Read setup answers from a JSON file.

## sync

Update the managed instructions from the project profile.

## guard

Say whether an approved task covers the work, for hooks and CI.

- `--hook {prompt,pre-edit}`: Run as a host hook; reads the hook input on stdin.
- `--ci`: Check the decisions exported for the changes since --base.
- `--base BASE`: Base revision for --ci (default origin/main).
- `--require-signed`: With --ci, fail while the base revision's approvals are local and cannot be verified.
- `--org-catalog NAME=PATH`: With --ci, the copy of the organization catalog that the lock calls NAME.
- `--json`: Print the result as JSON.
- `--format {text,sarif}`: With --ci, print the problems as SARIF 2.1.0 for code scanning instead of text.

## tools

Browse the tools of a company stack and their MCP servers, connect them or rehearse with mocks.

### tools list

List the known tools and whether an MCP server is on record.

- `--category CATEGORY`: Only one category. One of: issue-tracking, source-control, ci-cd, documentation, design, communication, time-tracking, hr, finance, crm, marketing, support, security, quality, observability, cloud, data, browser, testing, analytics, automation, product, identity, ide, registries, containers, api-management.
- `--brain BRAIN`: Only the tools a brain uses.
- `--mocks`: Only the tools that have a mock.
- `--json`: Print the entries as JSON.

### tools show

Show a tool: its servers, what they need and where that was verified.

- `ID`: Tool ID.
- `--json`: Print the entry as JSON.

### tools recommend

Match the project's tools and repository to the registry.

- `--json`: Print the result as JSON.

### tools plan

Show the MCP servers that would be configured, and what each person must provide.

- `TOOL ...`: Tool ID, or TOOL/SERVER to pick a server.
- `--host {claude-code,codex}`: Agent host to write for (defaults to the project's host).
- `--mock`: Connect local mocks with synthetic data instead.
- `--community`: Allow community-maintained servers.
- `--set TOOL.NAME=VALUE`: A setting a server needs, such as a subdomain (repeatable).
- `--token-env TOOL=VARIABLE`: Environment variable that holds the bearer token of a remote server (repeatable).
- `--log FILE`: With --mock: journal of the calls the agent makes.
- `--read-only`: Select each server's read-only mode when its publisher documents one, preferring a tool's server that has one.
- `--json`: Print the plan as JSON.

### tools apply

Write the accepted MCP servers to the host's project configuration.

- `TOOL ...`: Tool ID, or TOOL/SERVER to pick a server.
- `--host {claude-code,codex}`: Agent host to write for (defaults to the project's host).
- `--mock`: Connect local mocks with synthetic data instead.
- `--community`: Allow community-maintained servers.
- `--set TOOL.NAME=VALUE`: A setting a server needs, such as a subdomain (repeatable).
- `--token-env TOOL=VARIABLE`: Environment variable that holds the bearer token of a remote server (repeatable).
- `--log FILE`: With --mock: journal of the calls the agent makes.
- `--read-only`: Select each server's read-only mode when its publisher documents one, preferring a tool's server that has one.
- `--json`: Print the plan as JSON.
- `--yes`: Write live servers without asking: the team reviewed the plan.

### tools status

Show the recorded connections and what is missing on this workstation.

- `--json`: Print the status as JSON.

### tools remove

Remove connections from the host's project configuration.

- `TOOL ...`: Tool ID or server name.
- `--host {claude-code,codex}`: Agent host (defaults to the project's host).

### tools mock

Run a tool's mock MCP server on stdio: synthetic data, no network.

- `ID`: Tool ID.
- `--log FILE`: Append each tool call to this file.

### tools call

Call one tool of a mock and print its answer, without an MCP client.

- `ID`: Tool ID.
- `[NAME]`: Name of the mock's tool. Omit it to list them.
- `--args JSON`: Arguments as a JSON object.
- `--json`: Without a tool name: list the mock's tools as JSON.

### tools scenario

Write a starting scenario: the mocks' records retitled for this project, all synthetic.

- `[TOOL ...]`: Tools with a mock (defaults to the project's).
- `--task ID`: Title the records after this task's brief.
- `--brief TEXT`: Title the records after this text.
- `--force`: Replace an existing scenario file.

## profile

Change the project profile after setup: adopt or decline a pattern, add or remove a pack, role, tool, check or board, set the host, guard or research policy.

### profile adopt

Adopt a pattern or regulation: it becomes active. adopt rule PACK/RULE restores a declined rule.

- `PATTERN`: Pattern ID, from openguildkit recommend or patterns; or the word rule, followed by PACK/RULE.
- `[PACK/RULE]`: After the word rule: one rule, as AGENTS.md lists it under its pack.
- `--by INITIALS`: Your initials or team handle, not your full name: it is committed.
- `--reason WHY`: Why, in one line; recorded in the profile history (.openguildkit/project.json) and shown in AGENTS.md and preview.

### profile decline

Decline a pattern or regulation: it is not active and not proposed again. decline rule PACK/RULE sets one rule aside: no task is asked it.

- `PATTERN`: Pattern ID, from openguildkit recommend or patterns; or the word rule, followed by PACK/RULE.
- `[PACK/RULE]`: After the word rule: one rule, as AGENTS.md lists it under its pack.
- `--by INITIALS`: Your initials or team handle, not your full name: it is committed.
- `--reason WHY`: Why, in one line; recorded in the profile history (.openguildkit/project.json) and shown in AGENTS.md and preview.

### profile add

Add entries to a list of the profile.

- `FIELD`: The list to change. One of: board, check, convention, pack, required-board, required-rule, role, tool.
- `VALUE ...`: IDs, tool names or check commands.
- `--by INITIALS`: Your initials or team handle, not your full name: it is committed.
- `--reason WHY`: Why, in one line; recorded in the profile history (.openguildkit/project.json).

### profile remove

Remove entries from a list.

- `FIELD`: The list to change. One of: board, check, convention, pack, required-board, required-rule, role, tool.
- `VALUE ...`: IDs, tool names or check commands.
- `--by INITIALS`: Your initials or team handle, not your full name: it is committed.
- `--reason WHY`: Why, in one line; recorded in the profile history (.openguildkit/project.json).

### profile set

Set the host, guard, research policy, sector, approval mode, waiver policy, whether every rule is asked, the paths of the short lane, whether the requester of a task may approve it, the freeze of the project, the longest age of an approval, who clears a board's blockers (approver-roles), the paths closed to the agents (restricted-paths), or a setup answer.

- `FIELD`: The setting to change. One of: approval, approver-roles, ask-every-rule, freeze, guard, host, light-paths, max-approval-age, people-decisions, personal-data, research, restricted-paths, sector, separate-requester, waivers.
- `VALUE`: Its new value (light-paths: a folder or file glob such as 'docs/**', or none).
- `[PATH ...]`: light-paths and restricted-paths: more paths. approver-roles: the people of the role (VALUE is the board), or none.
- `--signers PATH`: approval signed: the allowed signers file, a path inside the project.
- `--approver NAME`: approval signed: a person whose signature approves a task; repeat for each.
- `--allowed-by NAME`: waivers allowed: a person who may waive a blocker; repeat for each.
- `--max-days DAYS`: waivers allowed: how long a waiver may last, 1 to 366 days.
- `--by INITIALS`: Your initials or team handle, not your full name: it is committed.
- `--reason WHY`: Why, in one line; recorded in the profile history (.openguildkit/project.json).

### profile export

Print the setup answers that give another repository this profile's patterns, packs, boards and settings, for openguildkit init --answers FILE there.

## alerts

Import scanner reports into the project's dependency alert register and review the alerts.

### alerts import

Merge an npm audit, pip-audit, OSV-Scanner or Dependabot JSON report.

- `REPORT`: The scanner's JSON report.
- `--task TASK`: Link the report's alerts to this task.
- `--scope SCOPE`: Name of the project part the report covers, such as front or services/api: the import resolves only the alerts of that scope. Without it, only alerts without a scope.
- `--json`: Print what changed as JSON.

### alerts list

List the alerts of the register.

- `--status STATUS`: Only this status (repeatable). One of: open, confirmed, dismissed, resolved.
- `--task TASK`: Only the alerts linked to this task.
- `--without-task`: Only the alerts no task is linked to.
- `--json`: Print the alerts as JSON.

### alerts set

Mark an alert open, confirmed, or dismissed with a reason.

- `ALERT`: Alert ID, or ecosystem:package:ADVISORY for any of its advisory IDs.
- `--status STATUS`: Review status. One of: open, confirmed, dismissed, to-verify.
- `--by INITIALS`: Your initials or team handle, not your full name: it is committed.
- `--reason WHY`: Why; required to dismiss.

### alerts accept

Record, at a terminal, why a person accepts a confirmed alert.

- `ALERT`: Alert ID.
- `--by INITIALS`: Your initials or team handle, not your full name: it is committed.
- `--reason WHY`: Why the risk is accepted.

### alerts severity

Set, at a terminal, the severity of an alert, such as one pip-audit reports without any.

- `ALERT`: Alert ID.
- `--level {low,moderate,high,critical}`: The severity to record.
- `--by INITIALS`: Your initials or team handle, not your full name: it is committed.
- `--reason WHY`: Why, such as the advisory's CVSS score.

### alerts link

Link an alert to the task that handles it.

- `ALERT`: Alert ID.
- `--task TASK`: Task ID.

### alerts tasks

List the confirmed alerts no task handles, with the task each one gets.

- `--open`: Open each task as a draft and link its alert to it.
- `--json`: Print the alerts and their tasks as JSON.

## market

Create and update a market dossier, check it and list the competitor sources due for review.

- `MODE`: new: create an empty dossier; describe: change its title, market, audience or feature; competitor: add a competitor or substitute; observe: record a dated, sourced observation; unknown: add (or --remove) what is still unknown; watch: follow a public page of a competitor; checked: record that a watched page was reviewed with no change; change: record a verified change, which marks its watched page checked; provided: record that a person reviewed a watched page and provided it (local-only research); pause: pause the watch; resume: resume the watch; check: validate and list the gaps; due: list the watched sources to review.
- `[DOSSIER]`: Dossier ID in .openguildkit/market/.
- `--all`: due: every dossier of the project.
- `--title TITLE`: new, describe: the title.
- `--market MARKET`: new, describe: the market.
- `--audience AUDIENCE`: new, describe: the audience.
- `--feature FEATURE`: new, describe, observe: the feature.
- `--competitor COMPETITOR`: Competitor ID, a lowercase slug.
- `--name NAME`: competitor: its name.
- `--kind KIND`: competitor: direct or substitute; watch: what the page is, such as release notes.
- `--segment SEGMENT`: competitor: the segment it serves.
- `--url URL`: competitor, watch, checked, provided: a public https page.
- `--observation OBSERVATION`: observe: observation ID; an existing ID is replaced.
- `--claim CLAIM`: observe: what the competitor offers.
- `--source SOURCE`: observe: document or page the claim comes from; change: the page.
- `--date DATE`: observe, change: the date the information dates from, YYYY-MM-DD; checked, provided: today by default.
- `--what WHAT`: change: what changed.
- `--verified-by VERIFIED_BY`: change: the person who verified it.
- `--by INITIALS`: Your initials or team handle, not your full name: it is committed.
- `--text TEXT`: unknown: what is still unknown.
- `--remove`: unknown: remove the text instead of adding it.
- `--every-days DAYS`: watch: review interval in days (30 by default).
- `--json`: check, due: print the result as JSON.

## storybook

Compose the company Storybook, record its stories and extract a design system.

Create the project Storybook with npm create storybook@10.6.6. storybook compose prints a minimal .storybook/main.ts when the project has none.

### storybook compose

Add a published Storybook to the refs file that .storybook/main imports.

- `REF`: Ref ID, such as company; its stories are cited as storybook:REF_STORY_ID.
- `--url URL`: URL of the published Storybook.
- `--title TITLE`: Title shown in the Storybook sidebar.
- `--remove`: Remove this ref from the refs file.
- `--config-dir CONFIG_DIR`: Storybook configuration folder (default .storybook).
- `--json`: Print the result as JSON.

### storybook import

Compare Storybook index.json files, report what to map and record the known stories.

- `--project-index PATH`: The project's index.json or storybook-static folder (default storybook-static).
- `--company-index PATH`: The company Storybook's index.json or static folder.
- `--ref REF`: Ref ID of the company Storybook (default company).
- `--library PATH`: package.json of the company component library.
- `--package PATH`: The project's package.json (default package.json).
- `--json`: Print the result as JSON.

### storybook extract

Inventory the components, variants and style tokens of an existing React application. Supported: React function components (function declarations, arrow functions, forwardRef and memo) in .tsx and .jsx files, their props, literal defaults and string-union prop types, the export aliases and re-exports of .ts and .js index files, and CSS and SCSS stylesheets. Not supported: class components, Vue, Angular and Svelte components, CSS-in-JS and utility classes such as Tailwind's. The sources are read with text patterns, not a full parser: check the inventory before proposing.

- `--src PATH`: Source folder or file to scan, such as a screen; repeat to select several.
- `--preview PATH`: Screenshot the team may reuse; recorded with its hash, never analyzed.
- `--output PATH`: Inventory file (default .openguildkit/storybook/inventory.json).
- `--json`: Print the result as JSON.

### storybook propose

Write the proposals to validate from the inventory, keeping the decisions already made.

- `--inventory PATH`: Inventory file (default .openguildkit/storybook/inventory.json).
- `--proposals PATH`: Proposals file (default .openguildkit/storybook/proposals.json).
- `--json`: Print the result as JSON.

### storybook generate

Write tokens, stories and an index for the validated proposals; never overwrite edits.

- `--proposals PATH`: Proposals file (default .openguildkit/storybook/proposals.json).
- `--output PATH`: Output folder (default src/design-system).
- `--framework FRAMEWORK`: Storybook framework package for the types (default: the one in package.json, else @storybook/nextjs-vite for Next.js, else @storybook/react-vite).
- `--json`: Print the result as JSON.

## projects

Show several projects at a glance: guard, tasks, open points, alerts and check. Reads only.

- `[FOLDERS ...]`: Project folders, or folders whose subfolders are projects (default: the current one).
- `--search TEXT`: Find TEXT in the task briefs, decision reasons and rule IDs of every project.
- `--json`: Print each project and each match as JSON.
- `--surfaces`: Add what host scan finds in each folder, a project or not: agent tools, MCP servers, permissive settings, hooks, lock version and last decision.

## task

Take a task from the request to its closing: frame it, consult the boards, record the person's decision, then verify, complete and export it.

### task new

Create a task draft.

- `[BRIEF]`: Short description of the work.
- `--file FILE`: Read the brief from a UTF-8 Markdown or text file.
- `--id ID`: Use a readable lowercase task ID.
- `--follows TASK`: Link the task to an earlier task's decision.
- `--after TASK`: A task this one waits for; repeat it for each. task list --ready leaves the task out until they are done.
- `--requested-by NAME`: The person who asked for the work; required when the profile separates the requester from the approver, who cannot then be the same person.
- `--lane {light}`: Open the task in the short lane, which a person turned on in the profile: one board, no questionnaire, limited to --paths.
- `--paths GLOB ...`: With --lane light: the folders or files the task may change, inside the profile's light_paths. Write the brief first.

### task list

List the project's tasks with their status and next open point.

- `--status STATUS`: Only tasks in this status. One of: draft, consulting, reviewed, changes-requested, approved, done, done-with-reservations.
- `--owner OWNER`: Only tasks whose current decision this person took: the approval, the change request or the withdrawal of an approval.
- `--since DATE`: Created on or after YYYY-MM-DD.
- `--until DATE`: Created on or before YYYY-MM-DD.
- `--ready`: Only open tasks whose dependencies (task new --after) are all done.
- `--json`: Print the tasks as JSON.
- `--decisions`: List the decisions exported to .openguildkit/decisions, teammates' included.

### task retro
